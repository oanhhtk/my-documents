# 📘 Nuxt Persistent Storage Guide (Full Practical Guide for Nuxt 3/4)

Trong Nuxt 3/4, phần chạy trên server là **Nitro**. Lưu cache/KV phía server thường qua **Unstorage** (`useStorage`). Phía **browser** thì có **localStorage**, **sessionStorage**, **cookie**, v.v. Bài này gom cả hai thế giới và so sánh với **database**.

### 🎯 Goals

- Hiểu persistent storage là gì (client vs server)
- Biết **lưu ở đâu**, **config + code**, **nên / không nên** dùng
- Tránh lỗi SSR và lỗi khi scale

## 1. Storage layers (overview)

| Lớp                | Công cụ điển hình                                        | Chạy ở đâu                               | Ý chính                                                |
| ------------------ | -------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------ |
| **Client storage** | `localStorage`, `sessionStorage`, IndexedDB, `useCookie` | Chủ yếu browser (cookie kèm mọi request) | UI preference, state theo tab; **không** thay database |
| **Nitro storage**  | `useStorage()` + Unstorage drivers (`fs`, `redis`, …)    | Server (Nitro)                           | Cache, KV tạm, feature flags — **không** query như SQL |
| **Database**       | PostgreSQL, MySQL, MongoDB, …                            | Server / managed                         | Source of truth, query, transaction                    |

```text
[ Browser: localStorage / sessionStorage / cookie ]
        ↓ HTTP
[ Nuxt App ]
        ↓
[ Nitro Server — useStorage() / API routes ]
        ↓
[ Driver: memory | fs | redis | cloud … ]
        ↓
[ Database — khi cần dữ liệu nghiệp vụ & query ]
```

## 2. Quick reference

| Nhu cầu                     | Lớp                 | Gợi ý                                               |
| --------------------------- | ------------------- | --------------------------------------------------- |
| Theme, sidebar đóng/mở      | Client              | `localStorage` + `process.client`                   |
| State theo tab              | Client              | `sessionStorage`                                    |
| Locale gửi lên SSR          | Client + server đọc | `useCookie`                                         |

| User, đơn hàng, báo cáo     | Database            | ORM / SQL                                           |

<a id="toc-3" />

## 3. Client storage

Gồm mọi thứ lưu **trong browser** (hoặc cookie gửi kèm request). Không dùng làm nơi duy nhất cho dữ liệu quan trọng.

---

<a id="toc-3-ssr" />

### SSR and safety

- `localStorage` / `sessionStorage` / IndexedDB chỉ có trên **client**
- Trong `setup()` (có thể chạy server), không gọi `window` / `localStorage` trực tiếp

```ts
const theme = ref("light");

if (process.client) {
  theme.value = localStorage.getItem("theme") || "light";
}
```

---

<a id="toc-3-cookie" />

### Cookie

Dùng khi cần server (SSR, API) **đọc được** giá trị từ request, hoặc session.

- Preference không nhạy cảm: `useCookie` với `sameSite` / `secure` hợp lý
- Token nhạy cảm: ưu tiên **`httpOnly` do server set**, không đọc bằng JS client

```ts
const locale = useCookie("locale", {
  default: () => "vi",
  sameSite: "lax",
  secure: process.env.NODE_ENV === "production",
});
```

---

<a id="toc-3-ls" />

### `localStorage` and `sessionStorage`

**`localStorage`**

- UI state (dark mode, wizard step), không chứa secret
- User có thể sửa / xóa

**`sessionStorage`**

- Giống localStorage nhưng **mất khi đóng tab**

---

<a id="toc-3-idb" />

### IndexedDB

- Data lớn hơn hoặc offline (PWA)
- Phức tạp hơn localStorage; vẫn là **client-only**

---

<a id="toc-3-pinia" />

### Persist Pinia (client-only)

Pinia **core** không có tùy chọn `persist`; cần plugin kiểu **pinia-plugin-persistedstate** (hoặc tự serialize vào `localStorage`). Ví dụ khi đã cấu hình plugin:

```ts
export const useCartStore = defineStore("cart", {
  state: () => ({
    items: [] as Array<{ id: string; qty: number }>,
  }),
  persist: true,
});
```

Chỉ persist field cần thiết; xóa khi logout; không coi đây là lớp bảo mật chính.

<a id="toc-4" />

## 4. Nitro storage (Unstorage)

Nitro tích hợp **Unstorage**: một API key–value, nhiều **driver** (memory, file, Redis, cloud, …).

---

<a id="toc-4-persist" />

### What does persistent mean on the server?

Ở đây **persistent** nghĩa là: sau khi **restart process**, data vẫn còn **nếu** driver ghi ra nơi bền (disk, Redis, blob, …). **Memory** thì restart là mất.

| Loại                                 | Có mất khi restart không                                                                        |
| ------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `memory`                             | Có — mất                                                                                        |
| `fs` / Redis / cloud (đúng cấu hình) | Thường vẫn còn sau restart app (tuỳ persistence của Redis/cloud provider, eviction, xóa volume) |

**Không persistent (biến trong RAM process):**

```ts
let count = 0;
```

**Persistent qua storage (ví dụ đã cấu hình mount `db`):**

```ts
const storage = useStorage("db");
await storage.setItem("count", 1);
```

---

<a id="toc-4-arch" />

### Architecture

```text
[ Browser ]
     ↓
[ Nuxt App ]
     ↓
[ Nitro Server ]
     ↓
[ Storage (Unstorage) — mount name, ví dụ "db", "cache" ]
     ↓
[ Driver: memory | fs | redis | netlify-blobs | … ]
```

---

<a id="toc-4-api" />

### Unstorage and `useStorage`

- **Unstorage** = abstraction key-value, cùng API cho nhiều backend
- Trong Nitro (server routes, server utils): dùng **`useStorage('tên-mount')`**. Mount phải khớp `nitro.storage` trong config (ví dụ `db`, `cache`).

```ts
const storage = useStorage("db");
await storage.setItem("user:1", { name: "Oanh" });
```

---

<a id="toc-4-drivers" />

### Drivers — where data lives

**1. Memory (phù hợp dev ngắn / cache chỉ trong process)**

```text
driver: 'memory'
```

- RAM của process → restart thường mất hết (không coi là persistent)

**2. Filesystem (`fs`)**

```ts
driver: "fs",
base: "./.data",
```

- File dưới thư mục base (ví dụ `.data/db/...` tùy cách mount và key)

**3. Redis**

```ts
driver: "redis",
// url / host: khai báo theo tài liệu driver Nitro/Unstorage & env
```

- Nhanh, hay dùng TTL, scale tốt cho cache

**4. Cloud (ví dụ Netlify Blobs)**

```ts
driver: "netlify-blobs",
name: "db",
```

- Phù hợp serverless / edge deploy tương ứng nền tảng

---

<a id="toc-4-lifecycle" />

### Limits and when data is cleared

**Giới hạn (ý niệm):**

- **FS**: phụ thuộc disk; không phải giải pháp query/scale như DB
- **Netlify Blobs**: quota / request theo plan
- **Redis**: RAM; có eviction policy nếu cấu hình

**Khi dữ liệu bị clear (tùy driver):**

| Driver      | Thường clear khi nào                      |
| ----------- | ----------------------------------------- |
| memory      | restart process                           |
| fs          | xóa file / xóa thư mục base               |
| redis       | TTL hết hạn; hoặc manual; policy eviction |
| cloud blobs | quota, manual, lifecycle của provider     |

TTL có thể hỗ trợ tùy driver — luôn đọc doc driver và test trên môi trường thật.

---

<a id="toc-4-config" />

### Configuration in Nuxt

**Dev — filesystem (ví dụ mount `db`):**

```ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      db: {
        driver: "fs",
        base: "./.data",
      },
    },
  },
});
```

**Production** — thường đổi driver theo env (Redis, S3-compatible, blobs, …). Pattern hay gặp: dùng biến môi trường và cùng một tên mount (`db` / `cache`) để code `useStorage('db')` không đổi.

```ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      db:
        process.env.NITRO_STORAGE_DRIVER === "redis"
          ? { driver: "redis" /* + tuỳ chọn từ env */ }
          : { driver: "fs", base: "./.data" },
    },
  },
});
```

(Ví dụ minh hoạ — chi tiết `redis`/`netlify-blobs` cần khớp version Nitro và tài liệu Unstorage.)

### CRUD

```ts
const storage = useStorage("db");

await storage.setItem("user:1", { name: "Oanh" });
const user = await storage.getItem("user:1");
await storage.removeItem("user:1");
```

---

<a id="toc-4-keys" />

### Key design (important)

**Good:**

```text
user:1
user:1:settings
user:1:location:1
cache:weather:hcm
```

**Bad:**

```text
data
list
allUsers
```

Cấu trúc gợi ý:

```text
<prefix>:<entity>:<id>[:<sub>]
```

Tránh một key chứa **array rất lớn**; chia nhỏ theo id hoặc pagination.

---

<a id="toc-4-ttl" />

### TTL and best practices

- Chia nhỏ data; tránh overwrite cả “list khổng lồ” mỗi lần
- Dùng prefix: `cache:`, `user:`, `session:`
- TTL: **tùy driver** — nếu hỗ trợ, có thể truyền tùy chọn TTL theo API của driver; nếu không, tự invalidate bằng version key (`cache:products:v2:list`)

Ví dụ ý tưởng (chỉ dùng nếu stack của bạn hỗ trợ đúng API):

```ts
await storage.setItem("cache:key", data /* , { ttl: 60 * 10 } */);
```

---

<a id="toc-4-use" />

### Use cases and Map example

**Nên dùng Nitro storage:**

- Cache API, feature flags, config snapshot, session nhẹ, dữ liệu tạm

**Không nên:**

- Hệ thống user/order/payment làm source of truth
- Search/filter phức tạp, analytics nặng

**Map app — gợi ý key:**

```text
user:1:location:1
user:1:location:2
user:1:locations → [1, 2, 3]   // index nhẹ, không nhồi full object lớn
```

<a id="toc-5" />

## 5. Database

Dùng khi cần:

- Query (`WHERE`, join, aggregation)
- Transaction, constraint, migration
- Dữ liệu nghiệp vụ dài hạn và nhất quán giữa mọi client

Nuxt không thay DB — Nitro/Unstorage **không** là chỗ thay thế PostgreSQL/MySQL cho core domain.

---

<a id="toc-6" />

## 6. Storage vs database

**KV (Nitro storage):**

```text
user:1 → { name: "Oanh" }
```

- Nhanh, đơn giản, không SQL query

**Database:**

```sql
SELECT * FROM users WHERE age > 20;
```

- Query, relation, transaction

**Quy tắc:**

> Cache / tạm / flags → **Storage**  
> Dữ liệu thật / báo cáo / thanh toán → **Database**

<a id="toc-7" />

## 7. End-to-end architecture

```text
Nuxt
 ↓
Nitro — useStorage (cache / KV)
 ↓
Database (source of truth)
```

**Ghi nhớ:**

- Storage không phải DB; không kỳ vọng query hay transaction đầy đủ
- Cẩn thận concurrency; data lớn nên đẩy về DB hoặc object storage phù hợp

<a id="toc-8" />

## 8. Checklist

- [ ] Dữ liệu thuộc **browser**, **Nitro KV**, hay **DB**?
- [ ] Có cần SSR đọc giá trị không? → cookie / server
- [ ] Có secret không? → không `localStorage`; token ưu tiên `httpOnly`
- [ ] Nitro driver nào? restart thì data còn không?
- [ ] Có cần TTL / invalidate không?
- [ ] Có cần query/transaction không? → DB

---

<a id="toc-9" />

## 9. Conclusion

- **Client storage** (`localStorage`, `sessionStorage`, cookie, IndexedDB): UI và trạng thái browser; nhớ SSR boundary
- **Nitro + Unstorage**: persistent **trên server** khi dùng driver bền; nhớ “memory ≠ persistent”
- **Database**: nguồn dữ liệu chính khi cần query và độ tin cậy nghiệp vụ

**Tóm tắt nhanh:**

- Dev: hay dùng `fs` cho KV nhanh
- Prod: `redis` / cloud driver phù hợp infra
- Key nhỏ, có prefix; tránh array khổng lồ một key
- Cache → storage; dữ liệu thật → database
